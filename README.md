# design-docs-guide

人とAIが設計書を一貫した品質で作成・更新・レビューするための、共通規約と運用ガイドを管理するリポジトリです。

各種設計書に共通する原則をまとめ、Cursor・Codex・Claude Codeなどを使うプロジェクトへ持ち込める構成にしています。設計書を作成する人、レビューする人、AIへの作業指示を整える人を対象とします。

## 目的

- 文書ごとの責務と記述粒度を明確にし、重複や不要な補足を抑える。
- 仕様変更の影響を関連文書へ反映し、文書間の整合性を保つ。
- 人が読みやすく、後続の設計・実装・検証で参照できる設計書を作る。

## 基本的な考え方

「文書ごとのテンプレート＋共通規約＋共通の作業手順」を基本とします。

テンプレートには、その文書の目的、責務、記述粒度、必須項目、参照資料、固有の確認観点を定義します。テンプレートと必要なスキルは各プロジェクトで用意します。

共通手順は、必要に応じて1つのスキルにまとめられます。文書ごとの専用スキルは、情報収集や検証などに固有の手順がある場合に使用します。スキルを使わず直接作業する場合も、共通規約を適用します。

## 使い方

1. [共通規約](./設計書共通作成更新規約.md)を読み、対象文書と作業範囲を確認する。
2. プロジェクトの前提、関連仕様、対象テンプレート、使用するスキルを確認する。
3. 不明点を対話で整理し、計画を確認して作成・更新・レビューを進める。
4. 共通規約のチェック項目と文書固有の観点で確認し、人がレビューする。

AIに依頼するときは、次のように参照資料と作業を指定できます。参照先のパスは実際の配置に合わせます。

```text
作業前に「設計書共通作成更新規約.md」の本文を読み、適用してください。
対象文書と対応テンプレート、関連仕様を確認してから、作成・更新の計画を整理してください。
重要な不足情報は質問し、参照した資料と関連文書への影響を報告してください。
```

他プロジェクトへ導入する場合は、[運用マニュアル](./設計書作成運用マニュアル.md)の「ツールへの導入」を参照してください。既存の入口ファイルへ参照指示を追記し、配置に応じてリンクを調整します。

導入後は、新規セッションで入口と共通規約の本文が読み込まれることを確認します。ツール別の読み込み条件と確認状況も運用マニュアルに記載しています。

## このリポジトリを更新するとき

最新の`develop`から作業ブランチを作成し、変更をpushしたら`develop`を対象とするPRを提出します。ユーザーが内容を確認してからマージする運用とします。詳細は[CONTRIBUTING.md](./CONTRIBUTING.md)を参照してください。

共通規約と関係する既存資料を読み、変更の根拠と影響範囲を確認します。必須事項は共通規約、作業手順と推奨事項は運用マニュアル、参照指示は入口ファイルで管理します。

READMEは目的と使い方を案内する入口として保ち、詳細は対応する文書へのリンクで参照します。更新後は、関連文書との整合性と相対リンクを確認します。
